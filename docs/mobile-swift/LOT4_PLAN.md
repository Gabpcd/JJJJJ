## Corrections vs plan (faits du dépôt qui contredisent ou précisent le plan l.202-210 et §4.1 l.106)

1. **Super-likes : la mécanique n'existe plus.** `fn_enregistrer_swipe` réécrit `SUPER_LIKE` en `FAVORI` (l.32771) ; aucune fonction de quota (« 5/jour » de `CLAUDE.md` Sprint 13) n'existe dans le dump. **Badges et streaks** sont des effets serveur des triggers `trg_award_badges_swipe` (l.75708 → `fn_award_badges_swipe` l.20475, `PREMIER_SWIPE` l.20488, `EXPLORATEUR` l.20494, `TOP_SWIPER` l.20500) et `trg_update_streak_on_swipe` (l.76412 → l.64476) ; le web ne les affiche plus (`MesMatches` non routé, `src/App.tsx` l.88 ; `CelebrationMatch` monté seulement dans `src/lib/nativeBack.customModals.test.tsx` ; `fn_ma_streak` l.41010 sans appelant dans `src/`). Le natif n'ajoute ni bouton super-like ni écran streak/badges ; la preuve est SQL (lignes `badges_soignant`, `streaks_soignant` après un swipe natif). `fn_badge_stats` (l.20518) reste au profil (lot 3, `src/pages/ProfilSoignant.tsx` l.218).
2. **Évaluations : la vue `evaluations_publiees` (l.69517-69543) n'est accordée qu'à `service_role` (l.86074)** et n'est pas `security_invoker` : le client ne peut pas la lire et ne doit jamais l'obtenir (elle contournerait RLS).
