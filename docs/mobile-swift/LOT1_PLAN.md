### 2.2 Extension de `Gateways` (corrigé)

`Gateways` (`Ports.swift` l.68-77) est un struct à 4 `public var` et un unique `public init(auth:role:missions:clock:)` (l.74-76). Swift refuse les propriétés stockées en `extension` ; la voie la moins invasive est **l'ajout de champs dans le corps du struct** avec une valeur par défaut « port non câblé », en conservant l'init l.74-76 au caractère près (il compile grâce aux défauts) et en ajoutant un second init complet :

```swift
// Ports/Lot1Ports.swift : protocoles + stubs
public struct UnwiredDashboardPort: DashboardPort, Sendable {
    public func dashboard(context: MissionReadContext) async throws -> DashboardSnapshot {
        throw JoleneError(.contract, "Port tableau de bord non câblé (lot 1, T1).")
    }
}
// Ports/Ports.swift : seule modification autorisée (exception PRINCIPES §2)
public struct Gateways: Sendable {
    public var auth: AuthPort; public var role: RolePort; public var missions: MissionsPort; public var clock: ClockPort
    public var dashboard: DashboardPort = UnwiredDashboardPort()
    public var candidature: CandidaturePort = UnwiredCandidaturePort()
    // … presence, favoris, mesMissions, compte, audit, flags, recovery, justificatifs
    public init(auth: AuthPort, role: RolePort, missions: MissionsPort, clock: ClockPort = SystemClock()) { /* inchangé */ }
    public init(auth:role:missions:clock:dashboard:candidature:presence:favoris:mesMissions:compte:audit:flags:recovery:justificatifs:)
    public var unwiredPorts: [String] { /* noms des champs encore stubs */ }
}
```

Conséquences vérifiées : les 5 sites `Gateways(` (`DemoWorld.swift` l.29, `SupabaseGateways.swift` l.35-40, `SessionControllerTests.swift` l.168-175, `MissionsModelsTests.swift` l.63, `SessionStoreTests.swift` l.28) compilent sans changement ; `SessionController` (`private let configured: Gateways` l.27, init l.37, `gateways(for:)` l.51-53) reste intouché, donc une seule garde d'epoch. Un conteneur séparé `Lot1Gateways` est écarté (deux chemins d'invalidation d'identité). Parade au stub silencieux (règle « un gap connu reste verrouillé ») : un test par monde, `DemoWorldTests.testAucunPortNonCable` et `SupabaseGatewaysTests.testAucunPortNonCable`, qui affirment `unwiredPorts.isEmpty` ; le message du stub cite T1.

### 2.3 Nouveaux ports (tous `Sendable`) et timeout

Les modèles d'écran ne peuvent pas l'appeler. `SessionController.swift` n'est pas dans la liste gelée de PRINCIPES l.31 : T1 extrait le corps l.229-251 dans `Sources/JoleneCore/Session/Bounded.swift` (`public func bounded<T: Sendable>(timeout: TimeInterval, _ operation: @escaping @Sendable () async throws -> T) async throws -> T`, message `SessionController.timeoutMessage`), fait de `SessionController.bounded` un délégué d'une ligne, et expose `resolutionTimeout` en `public nonisolated let`. ### 2.4 Réponses jsonb en HTTP 200

`fn_dashboard_soignant_complet` l.27934, `fn_mes_favoris_etablissements`, `fn_supprimer_compte_rate_limited`, `fn_postuler_mission`, `fn_confirmer_presence_mission` (l.24612-24617 : `{"error": "Mission introuvable"}`, `{"error": "Cette mission n'est plus active."}`) renvoient `{"error": "..."}` avec HTTP 200. Helper unique `RPCResponse` (`JoleneSupabase/RPC/RPCResponse.swift`) : lecture tolérante, chaque clé est optionnelle sauf celles qui conditionnent une action (`candidature_id`, `contrat_id` : absentes ou vides → `JoleneError(.contract)`). Un gateway qui ne teste que l'erreur PostgREST afficherait un faux succès : test obligatoire par RPC et par forme de réponse.

**Discrimination par clés, indépendante de `success` (règle normative pour T1 et T6a).** Les délégués de `fn_confirmer_action_planning_v1` renvoient leurs refus **sans clé `success`** : `{choix_requis:true, error:'Choisissez votre mode de contrat.', options}` (`v_resolution - 'ok'`, l.47970 et l.36753), `{error, documents_requis_pour, lien_documents}` (l.47991-47996 et l.36758-36763), `{error, code:'PLAFOND_48H_HEBDO' | 'PLANNING_HEBDOMADAIRE_INDISPONIBLE', …}` (l.36788-36824). Un décodeur qui ne lirait les refus structurés que sous `success:false` (ou `ok:false`) les transformerait en `.unknown` : pas de sheet de choix de contrat (missions `TOUS`), pas de renvoi vers les documents, code du plafond 48 h perdu. Ordre de lecture = celui du web (`DetailMissionSoignant.tsx` l.758-762 et l.814-821 : `choix_requis` testé avant `error`) ; la première règle qui s'applique gagne :
