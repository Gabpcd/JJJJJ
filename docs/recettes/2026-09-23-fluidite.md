## JOL-01 — Documents sans dossier

Avant : l’absence normale du profil professionnel déclenchait une erreur réseau et un réessai sans issue. Après : préparation facultative, accès à Explorer, contrats et DPAE distincts. Une vraie panne conserve une alerte et un réessai. Des règles absentes ou un mode d’exercice inconnu ne permettent pas d’annoncer que tous les documents obligatoires sont validés.

Extrait ARIA avant, copié exactement depuis la [reproduction locale de l’audit](../../recette/2026-09-23-fluidite/avant/finding-documents-profil-absent.txt) :

```yaml
    - alert:
      - img
      - heading "Documents indisponibles" [level=2]
      - paragraph: Vos documents sont temporairement indisponibles. Vérifiez votre connexion puis réessayez.
      - button "Réessayer":
        - img
        - text: Réessayer
```

Extrait ARIA après, [WebKit 390](../../recette/2026-09-23-fluidite/apres/soignant-public/documents-minimal-390.txt) :

```yaml
    - region "Votre dossier, quand vous en aurez besoin":
      - heading "Votre dossier, quand vous en aurez besoin" [level=2]
      - paragraph: Vous pouvez découvrir les missions sans ajouter de document. Vous préparerez votre dossier professionnel lorsque vous souhaiterez candidater.
      - button "Explorer les missions"
      - button "Préparer mon dossier"
```

Assertions : absence d’alerte pour le compte minimal ; les trois onglets aboutissent ; une réponse 503 donne « Documents indisponibles » sans succès trompeur ; Réessayer avec une pièce valide rétablit le rendu. Les tests unitaires couvrent aussi le mode inconnu, les règles et l’invalidation du cache après modification des documents.

## JOL-02 — Parrainage sans code

Avant : QR et actions de partage disponibles avec `?ref=` vide. Après : état d’attente explicite, exploration libre, aucune action de partage personnel tant que le code manque. Chargement, panne et absence de code sont distincts. Au retour d’un code, le lien attribué et la progression financière réapparaissent ; la confirmation de copie suit la réussite effective du presse-papiers. Le même principe s’applique à l’établissement.

Extrait ARIA [avant](../../recette/2026-09-23-fluidite/avant/finding-parrainage-code-vide.txt) :

```yaml
  - img "QR code de ton lien de parrainage"
  - text: https://jolene.app/inscription/soignant?ref=
  - button "Copier le lien":
    - img
    - text: Copier le lien
```

Extrait ARIA [après](../../recette/2026-09-23-fluidite/apres/soignant-public/parrainage-minimal-390.txt) :

```yaml
  - region "Votre lien de parrainage n’est pas encore disponible":
    - heading "Votre lien de parrainage n’est pas encore disponible" [level=2]
    - paragraph: Votre code personnel sera disponible après la création de votre dossier professionnel. Vous pouvez continuer à explorer les missions sans le préparer maintenant.
    - link "Explorer les missions":
      - /url: /soignant/recherche-missions
    - link "Préparer mon dossier":
      - /url: /soignant/profil
```

Assertions : zéro QR, zéro bouton « Copier le lien », zéro lien contenant `?ref=` avant code. Après reprise, code fictif `JO-ABC123` présent dans chaque lien et texte exact « Plus que 180 € de missions avant vos primes ». Aucun partage réel envoyé.

## JOL-04 — Ouverture du détail depuis Swipe

La capture du pointeur par le parent empêchait le clic souris d’atteindre la carte. Le correctif distingue un tap/clic court du glissement horizontal, du geste vertical et de l’annulation. Le clavier reste pris en charge ; un drag ne doit pas ouvrir le détail.

La preuve avant est une **trace d’événements, pas un snapshot ARIA**. Les fichiers originaux [Chromium](../../recette/2026-09-23-fluidite/avant/swipe-clic-chromium.json) et [WebKit](../../recette/2026-09-23-fluidite/avant/swipe-clic-webkit.json) donnent exactement :

```json
"pointerOpened": 0,
"keyboardOpened": 1
```

L’audit avait déjà confirmé que le vrai tap tactile fonctionnait : le défaut initial était le clic souris, pas une panne tactile générale.

Après : le cas `Swipe : clic ou tap ouvre le détail, un déplacement horizontal ne le déclenche pas` réussit sur les trois configurations du [résultat navigation](../../recette/2026-09-23-fluidite/resultats/navigation.json). Les assertions exactes du test portent sur :

```ts
if (isMobile) await titre.tap(); else await titre.click();
const detail = page.getByRole('dialog', { name: 'Remplacement infirmier de jour', exact: true });
await expect(detail).toBeVisible();
```

Après fermeture puis déplacement de 40 px : `await expect(detail).toHaveCount(0)`, carte toujours visible et zéro mutation métier. Aucun dump ARIA spécifique au geste n’était conservé par cette suite ; il n’est pas remplacé ici par un arbre reconstitué. Les cinq tests unitaires de gestes complètent le cas E2E.

## JOL-05 — Rubriques établissement sans dossier

`AccesEtablissement` attend la résolution du périmètre avant de monter la rubrique. Un compte d’inscription minimal reçoit un état d’exploration, un compte identifié voit son vrai état vide, un refus de membership reste un refus et une panne donne Réessayer. ## Fluidité et corrections complémentaires

- **Cadre persistant** : les routes imbriquées conservent AppShell, navigation et layout. Une seule zone principale, mêmes guards de rôles. Les tests vérifient le même élément de navigation et le même document pendant les changements d’onglet.
- **Explorer** : caches isolés par compte, critères et vue conservés, chargement/erreur/résultats distincts, invalidations ciblées du profil et de la RCP. Les documents supprimés sont exclus. Déconnexion : cache vidé.
- **Retour au scroll** : positions par entrée d’historique et onglet, restauration différée bornée puis arrêt sur interaction. L’observation de `#app-route-content` remplace le body à hauteur fixe ; trois parcours vérifient la position exacte après détail et après un autre onglet.
- **Carte** : Leaflet chargé à la demande, lien mission en navigation interne, retour vers la carte sans recharger le document. Les contrôles conservent les clics modifiés ; les textes de popup ne sont pas injectés comme HTML.
- **Navigation et profil** : lecture indexée par compte/rôle/établissement et invalidation après profil, activation libérale, avatar/logo et nom établissement. Test SALARIE→LIBERAL→SALARIE sans remontage ; périmètre du collaborateur distinct de son identifiant Auth.
- **Safari et Auth natif** : largeur du Popover profession mesurée avant ouverture ; aucune suppression globale d’erreurs. Cartes Auth natives non rétrécies et padding ajusté ; pile système iOS et retrait des liens Google Fonts seulement avec `VITE_NATIVE_BUILD=true`.
- **Formulaire mission** : introduction compacte unique et reprise de brouillon seulement lorsqu’un contenu existe. Alertes SIRET, contrat et vérification conservées.
- **Détail mission** : rémunération juste après le titre dans le DOM, avant établissement et planning. Le bloc financier a été déplacé sans modification de ses 5 207 caractères. Assertions pour `240,00 €`, `80%`, mentions salarié/libéral/rétrocession, une seule région financière, visibilité avant le pli et absence de débordement. Aucun calcul ni régime changé.
